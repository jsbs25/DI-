# 06 — 域名、DNS、HTTPS 与全球网络设计（Phase 2）

- **日期**：2026-11-12
- **前提**：用户已拥有域名；**不得擅自更换域名、不得擅自修改 NS、不得删除原有 DNS 记录**。本阶段仅设计，不改正式 DNS。

## 1. 域名与子域名规划（建议，待用户确认）

| 用途 | 建议主机名 | 指向 | 说明 |
|---|---|---|---|
| Web 前端 | `@` / `www` | Cloudflare Pages（自定义域） | SPA 入口，HTTPS 强制 |
| API | `api.<domain>` | Workers 自定义路由 或 过渡后端反代入口 | REST `/api/*`，CORS 白名单绑定前端域 |
| WebSocket | `ws.<domain>` 或 复用 `api.<domain>` | DO/Workers WS 或 过渡后端 WSS | Messenger `/ws` 与通话信令；优先同站简化证书与 Cookie 策略 |
| 静态/上传资源 | `cdn.<domain>` 或 R2 自定义域 | R2 公有读仅限非敏感资源；私有资源走 API 签名 URL | 头像公开策略需评审，聊天附件默认私有 |
| 预览/测试 | `staging.<domain>` / Pages 默认 `*.pages.dev` | 测试环境 | 正式切换前全链路验证 |

> 具体命名以用户域名与现有记录冲突检查结果为准。

## 2. HTTPS 与证书
- Pages/Workers/R2 自定义域使用平台托管证书（自动续期）— 配置步骤按官方文档执行。
- 过渡后端若自托管需 Let’s Encrypt/托管证书；**禁止明文 HTTP 生产登录**。
- HSTS、TLS 版本与安全头在边缘/反代层统一配置。

## 3. DNS 设计与变更流程
1. **盘点**：导出现有 DNS 全量记录（A/AAAA/CNAME/MX/TXT/CAA 等）并存档。
2. **计划**：仅新增/修改目标子域所需记录；保留邮件等无关记录不动。
3. **灰度**：先在 `staging` 或 Pages 预览域验证，再切主域。
4. **回滚**：保留旧记录值与 TTL 策略，切换失败即时恢复。

## 4. OAuth 与回调地址
- `APP_URL` 与各提供商控制台回调必须与生产域名一致（Google/WeChat 等）。
- `resolveAppUrl`/代理头在生产需与可信代理配置对齐，避免回调域错配导致登录失败。
- 变更顺序：部署可达环境 → 更新 OAuth 回调白名单 → 验证 → 再对外公告。

## 5. CORS 与同源策略
- 生产：`Access-Control-Allow-Origin` 精确到前端域名（及必要的桌面 scheme/本地 dev 白名单策略需单独设计），允许凭据场景谨慎配置。
- WebSocket：校验 `Origin`，拒绝非预期来源。
- 现有个别 `*` CORS（如 epub-proxy）需按资源敏感度收敛。

## 6. 全球访问与性能设计
| 区域 | 目标 | 策略 | 验证 |
|---|---|---|---|
| 欧洲/北美 | 低延迟 | Pages/CDN 边缘缓存静态；API 就近边缘或区域后端 | 真实拨测 **NOT TESTED** |
| 约旦/沙特/土耳其 | 可用与可接受延迟 | 同上；避免不必要跨区长连接；WS 心跳与重连 | **NOT TESTED** |
| 中国大陆 | 可达性不确定 | Cloudflare 免费边缘在部分地区可能受限；**不承诺稳定访问**；需真实网络测试并记录 | **NOT TESTED** |

- 优化项：静态资源 hash 缓存、图片压缩与按需加载、API 分页与索引、避免轮询改用 WS/节流、上传直传/分片（在免费额度内）。

## 7. 桌面端网络配置
- 保持 `EARTH_ONE_DESKTOP_URL`/等效配置指向可选环境（本地/测试/生产）；生产证书校验与更新通道分离。
- 离线/弱网：沿用现有错误处理并补充重试策略（实现阶段）。

## 8. 网络安全
- WAF/速率限制/Bot 防护（Turnstile 可选，免费）— 阶段 3+ 评估集成。
- DDoS 与滥用：边缘限流、上传大小与类型限制、认证端点保护。
